PubMed has a free, programmable door: E-utilities

esearch returns PMIDs for a query; efetch returns the records (title, abstract, authors, journal, MeSH).

Rules: send “tool” and your email; 3 requests/s, or 10 with a free API key. Space the requests out, or you get HTTP 429.

GET eutils.ncbi.nlm.nih.gov/entrez/eutils/
  esearch.fcgi?db=pubmed&retmax=50
  &term=("Anemia, Iron-Deficiency"[mh]
    OR "iron deficiency anemia"[tiab])
    AND ("Students"[mh] OR student*[tiab])

→ {"count": "397", "idlist": ["36554486", …]}

31:00–33:00. [mh] is a MeSH heading, [tiab] title/abstract. You already know these from PubMed’s Advanced search; the API is the same search, called by code. Spacing matters: DrNext measured 28 of 96 requests rejected when 10 were sent at once, and zero when they were spaced 100 ms apart. Short plain-word searches beside the MeSH query also helped recall in that benchmark.
