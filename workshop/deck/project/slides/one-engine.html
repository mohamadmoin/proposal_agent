59:30–61:00. Another assumption corrected — this time by the product owner, not by a test run. I assumed “separate service” meant clean separation. The owner’s reasoning: the Academy already runs a Django backend with the right keys; a second container, database and secret only adds work and failure points; and since each proposal is one streamed agentic run of 1–2 minutes, a task queue adds nothing. The fix was cheap because of an early design decision: the engine (engine/) never imports Django. A small script copies it into the Academy and records which commit it came from. Lesson: separate the logic from the host, and ask the people who run the system before adding moving parts.
